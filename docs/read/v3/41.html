第三卷 · 学校不是名字

依赖缺失

第 41 章 · 5,669 字 · 约 13 分钟

5月7日，星期四。

上午在图书馆，他做了三十道计算机网络的选择题，对十四道。

错的十六道里有九道在传输层。TCP 的序号、确认号、拥塞窗口，他每次都觉得会，做的时候又要在纸上画半天。

他把错题抄进本子，抄到一半，想起桌角那块硬盘。

十一点半，他收拾东西回家。

＊　＊　＊

到家，烧水，泡面。

面泡着的时候，他把硬盘插上。

硬盘转起来，灯一闪一闪。

他打开 D: 盘，先进 checkpoints。

里面只有一个文件：

0620_800epoch.ckpt　1.4GB

修改时间：2022/6/12 4:12。

他记得这个文件。训练断断续续跑了四天，这是第六百二十次迭代、第八百轮。他当时不知道哪个好，就留了最后一个。

旁边还有一个 configs 文件夹。

他点开，里面是 myvoice.yaml。

用记事本打开，前面几十行都是参数：

sample_rate: 22050
hop_size: 512
batch_size: 1
max_epochs: 1000

采样率是他自己改的。教程里写 44100，他嫌跑得慢，砍了一半。当时他觉得这叫“优化”。

后面有一段：

train_dataset: dataset/train
valid_dataset: dataset/valid

他把记事本关掉，去看 dataset。

里面只有三个文件夹：train、valid、test。

train 里两个 wav。

valid 里一个。

test 是空的。

六百多段切好的音频，不在了。

他记得自己当时把它们放在桌面上，后来 C 盘满了，他清理过一次。

清理的时候他以为这些在移动硬盘里都有一份。

＊　＊　＊

面好了。

他端着碗回到桌前，一边吃一边看那个 tools 文件夹。

里面有几个 Python 文件，一个 requirements.txt，还有一个 README.md。

README 是他自己写的，只有四行：

1. pip install -r requirements.txt
2. python preprocess.py
3. python train.py --config configs/myvoice.yaml
4. python infer.py --config configs/myvoice.yaml --out output/

他放下筷子，打开 PowerShell。

输入：

python --version

回车。

Python 3.12.4

他愣了一下。

2022 年他装的是 3.8。中间重装过两次系统，现在这个 3.12 是什么时候装的，他不记得了。

他打开 requirements.txt。

torch==1.11.0
torchaudio==0.11.0
numpy==1.21.5
librosa==0.9.1
praat-parselmouth
PyYAML
tqdm

他盯着第一行。

然后输入：

pip install -r requirements.txt

回车。

屏幕上开始滚字。

第一行是：

ERROR: Could not find a version that satisfies the requirement torch==1.11.0 (from versions: none)

底下还有一行：

ERROR: No matching distribution found for torch==1.11.0

他把这两行看了两遍。

＊　＊　＊

他先以为是自己没连网。

打开浏览器，能上。

又试了一次，还是同样的字。

他在搜索框里输入：

“Could not find a version that satisfies the requirement torch==1.11.0”

回车。

第一个结果是 Stack Overflow，2019 年的。

第二个是一个中文博客，标题是“pip 安装 torch 失败的一百种原因”。

第三个是 torch 官网的安装页。

他点进去，页面上有一个选择框：系统、包管理器、语言、计算平台。

他选 Windows、pip、Python、CPU。

下面出来一行命令：

pip3 install torch torchvision torchaudio

没有版本号。

他往下翻，看到一个表：torch 1.11 支持的 Python 版本，3.7 到 3.10。

他现在是 3.12。

＊　＊　＊

他坐在那儿，想了一会儿。

最直接的办法是装一个 Python 3.8。

他打开 python.org，找到 3.8 的下载页。

页面上写着：Python 3.8 is no longer supported。最后一个安全更新是 2024 年 10 月。

他又搜：“Python 3.8 Windows 安装包 2026”。

出来的第一条是一个论坛帖子，标题是“3.8 装不上 torch 怎么办”。

第二条是某个大学的镜像站。

他下载了一个 3.8 的安装包，六十多兆，下了一分半。

下完，他把鼠标停在安装包上，没有点。

装第二个 Python，要改环境变量，要分清哪个 pip 对应哪个 Python。他以前干过，干到一半把系统变量删错，重装了一次系统。

那次之后，他遇到环境问题就换项目。

换一个教程，换一个仓库，换一个“更适合新手”的方案。换到最后，什么都没跑起来，但每次换的时候都觉得自己在前进。

＊　＊　＊

下午两点，他没有装 3.8。

他打开 README.md，在末尾加了一行：

环境：Python 3.12.4（2026-05-07 检查）

然后新建了一个文本文件，命名：

环境记录.md

写：

# 2026-05-07

系统：Windows 11
Python：3.12.4
项目：D:\DiffSinger（2022 年，无 git）
checkpoint：0620_800epoch.ckpt（1.4GB）
训练数据：只剩 3 段

写完，他回到 PowerShell，试着只装新的 torch。

pip install torch torchaudio

这次装上了。

下载一点几个 G，进度条走了四分钟。

装完，他输入 python，再输入 import torch。

没报错。

他松了一口气。

＊　＊　＊

然后他跑 infer.py。

python infer.py --config configs/myvoice.yaml --out output/

回车。

屏幕上先出来一堆警告，红色的，关于 pkg_resources 已弃用。

然后：

ModuleNotFoundError: No module named 'modules'

他愣了一下。

modules 是项目里的一个文件夹。他打开 D:\DiffSinger，里面确实没有叫 modules 的文件夹。

有 models，有 utils，有 tools。

infer.py 第一行写着：

from modules.model import DiffSinger

他打开 models，里面是一个 model.py。

他把 infer.py 里的 modules 改成 models，保存。

再跑。

ImportError: cannot import name 'DiffSinger' from 'models.model'

他打开 models/model.py。

第一行是 class DiffSinger(nn.Module):。

名字是对的。

再往下看，文件末尾有一行被注释掉的代码，和一行没写完的 return。

这个文件是坏的。

＊　＊　＊

他往后靠在椅背上。

硬盘在桌上转，风扇声很轻。

他想起来了。

2022 年 6 月，他改过这个文件。

当时他想给模型加一个“呼吸音”的开关，改到一半，发现改不动，就把代码注释掉，跑了一次，出来还是四秒。

后来他没有改回去。

他现在用的 infer.py，配的是一个改了一半的 model.py。

＊　＊　＊

他把 model.py 从头看到尾。

四百多行。

有一半他看不懂。

大二那年他其实也看不懂。他照着一个教程一步一步做，教程说改哪里就改哪里，改完能跑，他就以为自己做出来了。

现在教程还在网盘里，但教程对应的代码版本是 2021 年的，他下的是 2022 年的分支。

两个版本的文件结构不一样。

＊　＊　＊

四点，他试了第三种办法。

他在 GitHub 上搜 DiffSinger，找到官方仓库。

仓库首页写着最新版本，2025 年更新。

他下载了 zip，解压，把 requirements.txt 打开。

torch>=2.1
numpy>=1.26

跟他硬盘里那份完全不一样。

他坐在那儿，看着两个文件夹：一个 2022 年的，一个 2025 年的。

旧的有权重，代码坏了。

新的有代码，权重不认。

＊　＊　＊

五点，他打开网页版 AI。

输入框里，他先打了一行：

“帮我写一个歌声合成项目”

看着这行字，他删了。

这句话他打过很多次。2023 年打过，2024 年打过，上个月打“帮我做一个完全个性化的 408 教程”也算一次。

每次打完之后，他都会得到一个漂亮的新东西，然后花两天时间配置，再花三天时间放弃。

他把输入框清空，重新打：

“我有一份 2022 年的 DiffSinger 代码，checkpoint 是 1.4GB，但代码里的 model.py 被改坏了。官方仓库已经更新到 2025 年，权重加载不了。现在只想让这个 checkpoint 跑出一段音频。应该先做什么？”

发出去。

AI 回了很长一段。

第一段说，建议先确认 checkpoint 的保存格式。

第二段说，可以用 torch.load 看一下 state_dict 的键名。

第三段给了一段代码：

import torch
ckpt = torch.load("0620_800epoch.ckpt", map_location="cpu")
print(ckpt.keys())
for k in list(ckpt["state_dict"].keys())[:10]:
    print(k)

第四段说，如果键名和现在的模型对不上，可以试着改键名，但要先知道原来模型的结构。

最后一段说：不建议在没有版本信息的情况下继续，最好重新训练。

陆沉把这段回答看完。

最后一句他同意。

但他没有关掉页面。

他把那段代码复制到 PowerShell 里，把路径改成自己的，回车。

屏幕上出来一堆红字：

UnpicklingError: invalid load key, '<'.

他查了一下，这个 checkpoint 不是用 torch.save 存的，是另一个框架的格式。

＊　＊　＊

六点，林知遥打来电话。

“你今天做了多少？”

“十二道。”

“上午不是做了三十道？”

“上午三十道，下午没做。”

电话那头停了一下。

“你在干嘛？”

“修一个东西。”

“修什么？”

“硬盘里的一个旧项目。跑不起来。”

“重要吗？”

陆沉想了想。

“不重要。”

“那你还修。”

“我想知道它为什么跑不起来。”

“你不是想知道它为什么跑得慢吗？”

“先跑起来才能知道慢不慢。”

林知遥笑了一声。

“你这个人。”

“怎么了？”

“没什么。”她说，“我今天跑了一趟东院，人事科那个李老师不在，公告也没出。”

“五月出？”

“去年是五月十二号。”她说，“今年不知道。”

“那你等？”

“等。”她说，“我这次不着急。上次就是太着急，看到一个岗位就往上冲。”

“嗯。”

“你呢？”她问，“数学看了吗？”

“……”

“陆沉。”

“明天看。”

“你昨天也说明天。”

“昨天在数名单。”

“数完了吗？”

“数完了。”

“那今天呢？”

“今天在修硬盘。”

电话那头安静了几秒。

“你高兴吗？”她问。

“什么？”

“修这个，你高兴吗？”

陆沉看着屏幕上那行 UnpicklingError。

“不高兴。”他说，“但我想修好。”

“为什么？”

“因为四年前我没修。”

＊　＊　＊

挂了电话，他坐了一会儿。

七点半，他下楼买了一个肉夹馍，上来一边吃一边继续。

这次他没有再试新的方法。

他打开 环境记录.md，往下写：

## 已试

1. pip install -r requirements.txt
   → torch==1.11.0 无 Python 3.12 的 wheel

2. 只装新版 torch
   → 装上，但 import modules 失败

3. 改 infer.py: modules → models
   → model.py 里 DiffSinger 类不完整（2022 年改到一半）

4. 下载 2025 官方仓库
   → requirements 不兼容，权重格式不认

5. torch.load checkpoint
   → UnpicklingError: invalid load key, '<'
   → 不是 torch.save 格式

写完，他盯着这五条看。

以前他不会写这个。

以前他遇到第一个报错，就换个教程；遇到第二个，就换个项目；遇到第三个，就在群里问“有没有大佬带”。

六次开始，每一次都有一份新的教程、一个新的文件夹、一个更好听的名字。

没有一次留下这样的记录。

＊　＊　＊

八点，他把 dataset 里剩下的三段音频听了一遍。

一段是他自己录的“啊——”，一段是念的歌词，一段有杂音，楼下有人在装修。

他记得那天。2022 年 6 月，宿舍楼下修路，他等到晚上十一点才开始录，录到一半，室友回来开门，那一声“咔”也录进去了。

他把三段音频的属性看了一遍：44.1kHz，16bit，单声道。

配置里写的是 22050。

数据是 44100。

他把这两个数字并排写在纸上，看了一会儿。

要么把三段音频重采样，要么改配置。改配置的话，权重认不认，他不知道。

然后他在 环境记录.md 最后写：

## 缺

训练数据：600 段 → 3 段
代码版本：无 git，model.py 被改坏
权重来源：不知道对应哪一版代码

写完，他加了一行：

## 下一步

不问“为什么慢”。先让它跑起来。
＊　＊　＊

九点，他做了一件很小的事。

他把硬盘里的整个 DiffSinger 文件夹复制了一份到电脑上，命名 DiffSinger-2022-备份。

复制到一半，提示空间不足。

他看了一眼 C 盘：还剩 8.2G。

他关掉复制，把桌面上几个没用的安装包删了，清空回收站，又删了两个游戏留下的文件夹。

再复制。

这次成功了。

＊　＊　＊

九点四十，他打开错题本。

5.7 那一格，他写：

网络 30 道，对 14。

硬盘 3 小时。

做题 12 道。

写完，他想了想，在后面补了一句：

以后只有星期天晚上碰硬盘。

然后他把错题本合上，打开 408 的教材。

第五章，存储器层次结构。

他翻到上次看到的那一页，页脚有一行自己写的小字：

“先看逻辑结构，再看物理存储。”

是 4 月 26 日写的。

他把书压平，从第一行开始看。
