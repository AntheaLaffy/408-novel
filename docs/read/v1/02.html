百分之六十二

第 2 章 · 3,187 字 · 约 7 分钟

三月的部门周会在每周三上午九点半，3F 大会议室，能坐二十个人，实际到十四个。

陆沉到的时候，靠墙的位置已经坐满了。他只好坐到桌子边上，正对着投影仪，屏幕一亮，眼睛就得眯起来。

蒋文斌站在前面，用激光笔点着 PPT 上的一张折线图。

“二月份，我们组的平均采纳率是五十八点七，部门第六。一月份是五十四，进步了。但是，”他把激光笔往下移，“部门的目标是二季度七十五。七十五是什么概念？就是你们每个人，平均每天有三分之二以上的代码不是自己敲的。”

底下有人笑。

“笑什么，这是好事。”蒋文斌说，“去年这个时候我们十四个人，今年九个人，需求涨了百分之四十。人少了，活多了，为什么还能交？就因为这个。”

他又翻了一页，是排行榜。

“表扬几个。唐宇，百分之九十一，全组第一。陆沉，六十二点三，进步最快。周晓枫，八十四，但是他情况特殊，他的数量不算最高，质量分最高。”

唐宇是去年夏天入职的应届生，二十三岁，头发很厚，桌上摆着三个手办。听见自己的名字，他有点不好意思地笑了一下。

“唐宇你讲讲，你怎么做到的？”

唐宇站起来，说了三句话：“多问。问清楚再让它写。写完自己跑一遍。”

“就这些？”

“就这些。”

“好，坐下。”蒋文斌说，“大家听见了，多问。”

陆沉在心里补了一句：问清楚，指的是问灵犀。

会议的后半段是事故复盘。

上周，唐宇负责的优惠券模块出了一次线上问题。灵犀按需求把“满 199 减 30”改成了“满 199 减 35”，改得很干净，单测也补了，MR 评审也是灵犀自己评的，评语写着“逻辑清晰，测试充分”。结果上线第二天，运营发现有一批“满 199 减 30”的定向券也被改成了减 35，一天多发了七万块。

复盘会上，蒋文斌问：“谁的责任？”

唐宇低着头：“我的。”

“你的什么责任？”

“我没有验证。”

“你为什么不验证？”

“因为……因为它测试都过了。”

会议室里安静了两秒。

蒋文斌没有发火。他把激光笔放下，说了一句在部门里流传很广的话：

“它测试都过了，这句话以后不要再说了。测试是它写的，代码是它写的，评审是它评的。你唯一能提供的，是‘我知道这个业务长什么样’。”

他说完，看了一眼陆沉。

“陆沉，你昨天那个空指针，也讲讲。”

陆沉愣了一下。

他昨晚花了一个小时写复盘，写到凌晨一点。他写了那一百三十七个离职账号，写了上游“删除即注销”的设计，写了十几个调用点里有几个没判空，写了他最初为什么会点下那个“应用”按钮。

他打开文档，念了两句，蒋文斌就抬手打断了他。

“这段删掉。”

“哪段？”

“‘因为用户中心把记录物理删除了，所以所有调用方都默认查得到’这一段。”

“可是这是根因。”

“根因在别的部门。”蒋文斌说，“你讲这个，别人听了只会觉得你在甩锅。你讲方法：遇到空指针，先问数据从哪儿来，再看调用链，最后决定修在哪一层。十五分钟，讲这个。”

陆沉看着自己的文档，没说话。

“有问题吗？”

“没有。”

“好，下一个。”

＊　＊　＊

中午，食堂。

陆沉端着餐盘找到周晓枫的时候，周晓枫正在用手机看一份 YAML 文件，一边看一边用筷子在米饭上画圈。

“你又吃这个？”

“这个便宜。”周晓枫把手机扣下，“十二块八，两荤一素。”

“你工资比我高。”

“我房贷比你房租高。”

陆沉坐下来，扒了两口饭，忽然问：“你采纳率多少？”

“八十四。”

“你怎么做到的？”

“我不追求这个。”

“啊？”

周晓枫把筷子放下，想了想，说：“我每天上班第一件事，不是写需求，是看昨天 Agent 们提交的东西。哪个 MR 被合了，哪个被打回了，哪个打回之后又被另一个 Agent 改回去了。我给它们建了一个评测集，两百多条，每条都标了‘这个改动不能破坏什么’。”

“这跟采纳率有什么关系？”

“关系就是，我知道它们什么时候会错。”周晓枫说，“你那个六十二，我不羡慕。你知道最吓人的是什么吗？是九十一。九十一意味着这个人几乎不写代码了，也几乎不知道 Agent 写的代码里有什么。”

“唐宇挺认真的。”

“他认真。他认真地在问问题。”周晓枫说，“但问题问得好不好，取决于他自己懂多少。他今年二十三，他还有时间。你今年二十四，你也有。”

陆沉笑了一下：“你这是在安慰我？”

“我这是在提醒你。”周晓枫端起汤碗，“采纳率是给上面看的，不是给你看的。你真正该看的，是你自己提交的那三分之一里，有多少是你想明白了的。”

陆沉低头吃饭。

过了一会儿，他说：“我昨天想了一件事。”

“嗯。”

“我想不起来，我上一次从零开始写一个类，是什么时候。”

周晓枫抬眼看他。

“去年八月。”陆沉说，“写一个单元测试。”

“那也不错了。我上次从零写，是上周，因为我那个评测集里的断言，Agent 写不出来。”

“你为什么写得出来？”

“因为我知道我要测什么。”周晓枫说，“这句话听着像废话，但大部分人不知道自己要测什么。他们只知道‘跑通’。”

他把最后一口饭吃完，端起餐盘。

“你那个空指针，最后修在哪儿了？”

“调用方。加了个快照兜底。”

“上游不改？”

“排期到四月。”

“那你那个兜底，三个月以后还要不要？”

陆沉愣住了。

他没想到这个。

“如果上游四月改好了，你这个兜底就变成了一段没人敢删的代码。”周晓枫说，“你得给它写个 TODO，写上失效条件。不然三年以后，新来的人会以为它是业务逻辑。”

“……我下午加。”

“现在加。”周晓枫说，“你现在还记得为什么写它。三天以后你就只记得‘这里本来就有’。”

＊　＊　＊

下午，陆沉试了一件事。

他把灵犀关掉了。

不是卸载，就是把侧边栏收起来，把快捷键改成一个他记不住的组合。然后他打开一个需求：给客户列表加分页，支持按名称模糊搜索，按创建时间倒序。

这个需求他做过至少二十遍。

他打开编辑器，手指放在键盘上，忽然发现自己不知道从哪儿开始。

不是不会。是那种明明知道该写 PageHelper.startPage()，却要先想一下参数顺序的迟钝。他写了十分钟，写了一个 Controller，一个 Service，一个 Mapper。写到 XML 的时候，他停住了：动态 SQL 的 <if> 标签里，test 属性的引号他记不清是单引号还是双引号。

他试了两次，报错。

第三次他写对了，但把 order by 拼在了 where 前面，跑起来 SQL 语法错误。

他盯着那段 SQL，脸有点热。

二十五分钟。一个他做过二十遍的分页。

他把代码删了，重新打开灵犀，输入：“给客户列表加分页，支持名称模糊搜索，按创建时间倒序，用 PageHelper。”回车。

十一秒。

代码出来了，注释齐全，参数校验也带了，连 @Validated 都加上了。

他看了一遍，觉得没什么问题，点了提交。

提交完，他坐在椅子上，忽然觉得这个下午过得非常漫长。

＊　＊　＊

六点四十，陆沉拿着报销单去找蒋文斌签字。

蒋文斌的工位在靠窗那一排，屏幕很大，桌上摆着一个保温杯和一个已经落灰的机械键盘。他正在看什么东西，看得很专注。

陆沉走过去，站在他侧后方，正准备开口。

他看见了那块屏幕。

是一个 Outlook 日历，日历上有一个会议邀请，标题是灰色的，但能看清：

组织架构调整沟通（勿外传）

时间是明天上午十点半，地点是 3F-小会议室 B。

下面附了一份名单，名单只露出前五行。

第一行是唐宇。

第二行是“赵启明”。

第三行是“赵启明”后面的一个名字，陆沉没看清。

第四行是“陆沉”。

第五行被任务栏挡住了。

蒋文斌像是感觉到了什么，动了一下鼠标，窗口瞬间切成了一个需求文档。

“有事？”

“报销。”陆沉把单子递过去，“打车去客户现场那次。”

蒋文斌接过单子，扫了一眼，签字。笔尖在纸上划了两下，很快。

“明天上午十点半，”他把单子递回来，没有看陆沉的眼睛，“你到我这儿来一趟。”

“好。”

陆沉拿着单子往自己工位走。

走到一半，他停下来，假装在看墙上的项目进度板。

进度板上贴着十几张便利贴，红黄绿三种颜色。他那张是黄色的，写着“启明对账导出——已上线”。

他看了大概十秒。

然后回到工位，打开招聘软件，把简历的“在职”改成了“在职-考虑机会”。

改完，他盯着那个下拉框看了很久，又改了回去。
